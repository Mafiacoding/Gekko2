# R1379-AOT3 — AOT2 continuation with PCSX2/GIF corrections

This checkpoint combines the owner's working R1378-AOT2 with the recovered
`Gekko2-R1379B-Source.zip`. The AOT2 input profile and existing Wii build
options are retained. It continues the full dynarec/PS2 accuracy project;
it does not certify that project complete.

## Changes

- The R1379B bounded XGKICK completion fix is integrated into the shared GIF
  parser. Incomplete PATH1 PACKED/REGLIST/IMAGE state cannot consume the next
  kick. PATH2 and PATH3 fragment continuation remains independent.
- VU1 XGKICK now transfers one quadword per two VU issue clocks with one
  initial issue-cycle credit. It reads live memory lazily, wraps the 16 KiB
  ring, exposes VPU_STAT bit 12, drains before another kick and at a real
  stop, and bounds malformed no-EOP BIOS packets to one physical ring.
  The temporary 16 KiB ring-copy buffer is removed. VU execution itself is
  still synchronous with the EE/VIF caller; this is not full GIF arbitration.
- PATH1 IMAGE EOP survives fragment boundaries and stops parsing after its
  remaining payload. Finishing PATH1 does not clear another path's IMAGE
  bookkeeping. Actual kick counters count kicks, not transport fragments.
- EE AOT can execute a legal delay slot after a terminal branch and can
  enter a selected straight-line handler as an existing delay slot. The
  live slot word/mapping and safe data address are checked separately after
  the branch retires. Annulled, unsafe, changed or nested-control slots
  decline before mutation. Every instruction keeps its original retirement
  and EE/IOP quantum; Count IRQ deferral across a branch is preserved.
- BC2F/T/FL/TL are implemented using VPU_STAT bit 8, including likely
  annulment. The scalar core and AOT include the same operation body.
- LQC2 to VF0 performs memory reads and discards writes. Its RAM proof
  retains the actual unmasked address and full 16-byte span. The runtime
  PPC block emitter also preserves VF0 while performing the read.
- J/JAL use the upper address bits of PC+4 across region boundaries in EE,
  IOP, the PPC emitter and AOT generation.
- New GIF/VU checkpoint fields are appended; older checkpoint payloads
  initialize added state without shifting existing offsets.

The VIF fill-mode/source-length and live MMIO fixes, DATE/CT24 semantics,
shared triangle edges, nearest/negative-repeat sampling, freeze fixes,
guarded successor lookup and GX source-upload reuse were already present
in the AOT2 base and remain present. DVD2048/single-data-track CD2448 CHD
support and its hunk cache remain present.

## Build and reproduction

Use the same workflow as R1378-AOT2, with your local BIOS/profile:

```sh
python3 tools/verify_ee_aot.py
python3 tools/verify_r1370_native.py
python3 tests/test_ee_aot_inputs.py
export DEVKITPRO=/absolute/path/devkitpro
bash tools/build_ee_aot.sh /absolute/path/profile.json
```

The output is `Gekko2-R1379-AOT3.dol` and `.elf`. The private build retains
512 EE entries, 256 IOP entries and 44/64 VU upper/lower words. EE contains
4,008 instruction bodies rather than AOT2's 3,536. The published source has
empty generated tables; private BIOS/profile/microcode bytes are excluded.
Always run the final MEM1 size gate; the test fixture derives its code arena
from actual ELF load spans so a growing image cannot overlap its heap.

Install the DOL as `apps/gekko2/boot.dol` and cold boot. Keep the existing
app assets and ARM worker. Existing EE JIT/blocks, IOP JIT and VU JIT controls
still gate their corresponding paths; no new setting is required.

## Evidence

Validation logs and final binary hashes are in `validation/aot3-*`.
The build passes 6,887 EE/IOP/VU interpreter comparisons, 39 CPU regression
binaries, 49 focused graphics/device regressions and three input/size suites.
The final ELF passes 114 linked AOT comparisons plus 8 BC2, 6 jump-region
and 2 production XGKICK oracles. The historical linked PPC delay/vector/chain
suite also passes 256 delay programs, 60 vector programs and seven chain
budgets. Some native regression suites overlap; these are execution counts,
not a claim of that many independent hardware conformance tests.
MEM1 static end is `0x81622620`, leaving 1,956,320 bytes before its limit.
Independent native tests check BC2 outcomes/annulment/overflow BD/EPC,
VF0 data-TLB access and jump-region boundaries. VU/GIF oracles check issue
clocks, live-source mutation, wrapping, repeated kicks, E drain, incomplete
BIOS packets, IMAGE EOP and independent path state. Linked PPC checks
execute the final target binary with modeled platform services.

On 12 October 2026 the owner reports that **AOT2** approximately halves BIOS
boot time and Tekken reaches nearly **0.30 FPS**. No exact boot duration,
repeat-run count or accompanying timing log was supplied. This is owner
hardware evidence for AOT2, not a local measurement or AOT3 result.

## Full-completion gaps

These are implementation work, not merely missing acceptance paperwork:

| Area | Still required |
| --- | --- |
| Full dynamic recompilation | General paired 64/128-bit allocation, audited helper contracts and safe patched tail links; all changed/unselected code still needs runtime paths |
| EE/IOP hardware fidelity | Cycle-cost/event model instead of one Count tick per EE retirement; broader privilege/COP exceptions, cache behavior and HLE/device audit |
| COP2 control | Full CTC2/FBRST read-only, reset/force-break and macro/micro synchronization behavior |
| VU pipeline | FMAC/MAC/status/CLIP publication latency, dependency stalls and exact floating-point corner cases; VU0 M synchronization |
| VIF/GIF | Asynchronous EE/VU scheduling, coordinated PATH priority/backpressure/MSKPATH3, STOP/force-break and complete NUM/ERR/FIFO state |
| GS/GX | Automatic MTBA, trilinear mipmap behavior and broader exact renderer coverage while preserving VRAM ownership/fallbacks |
| Disc/device compatibility | Multi-track/parent/split CHDs and monolithic files above 2 GiB; full game/device conformance |

The historical eight failures in `tests/test_vif.c` are not reported as
passing or repaired by this checkpoint. Broad differential agreement with
the current scalar core cannot prove hardware correctness where both paths
share the same incomplete model. Full completion requires independent
architectural oracles plus repeated BIOS/game tests on the Wii.

Primary references inspected in the included reference snapshot:
PCSX2 `GS/GSState.cpp` PATH1 termination, `VUops.cpp` XGKICK clocks,
`COP2.cpp` BC2 condition and `VU0.cpp` LQC2 VF0 read-discard behavior.
