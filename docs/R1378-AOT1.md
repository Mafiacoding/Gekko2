# R1378-AOT1: experimental hybrid EE static recompilation

Historical checkpoint: use the frozen AOT1 source archive for these commands.
The current tree builds AOT2; see `R1378-AOT2.md` for its workflow.

Based on the supplied R1378 graphics-audit source. This branch adds a local
EE-to-C generator and guarded execution before the existing JIT. The Wii C
compiler turns generated blocks into native PowerPC code at build time.
Quiver itself is a launcher; no Quiver or N64Recomp engine was imported.

Supported generated operations: ADDIU/DADDIU, SLTI/SLTIU, ANDI/ORI/XORI/LUI,
32/64-bit logical and wrapping register arithmetic, scalar shifts, MOVZ/MOVN,
HI/LO moves, existing no-op SYNC, J/JAL/JR/JALR, regular/likely integer
conditional branches (including REGIMM link forms), and guarded aligned
LB/LBU/LH/LHU/LW/LWU/LD/SB/SH/SW/SD RAM accesses. Upper GPR lanes are preserved.

Every generated instruction revalidates the current source word and mapping,
uses the existing preparation and full retirement helpers, and accounts its
scheduler slot. Blocks stop at branches; delay slots run through the existing
scalar core. Unsafe/MMIO memory, unsupported instructions, changed code,
interrupts, exhausted budgets and invalid entries return to the existing
execution paths. No timing checks or emulated work are fabricated.

This is **not a complete PS2 static recompiler**. Overflow/trap operations,
unaligned and quadword memory, MMI, COP0/COP1/COP2 and VU microcode are not
translated by this generator. They retain the existing emulator's paths and
its existing limitations. GS/GX, audio, IOP and PS2 hardware emulation remain
necessary. No improved physical Wii boot time or FPS has been measured.
The current per-instruction guards and helper calls can outweigh the savings.

## Reproduce with local private input

Run from the source root:

```bash
python3 tools/verify_ee_aot.py
python3 tests/test_ee_aot_inputs.py
../ee_aot_profile_host /absolute/path/bios.bin /absolute/path/profile.json 50000000
export DEVKITPRO=/absolute/path/devkitpro
bash tools/build_ee_aot.sh /absolute/path/profile.json
```

The bounded host profiler samples real entry points before EE/IOP scheduler
slices. It is neither an exhaustive control-flow map nor a physical Wii
profile. Code words observed during that run may later change; live guards
decline them. The generator defaults to 1,024 supported observed entries
and 32 instructions per block, ordering candidates by sampled hits. The
optional `--max-blocks` limit accepts 1..4096. The Wii build rejects static
segments exceeding MEM1 or leaving under 1 MiB for platform runtime/stack;
this is an address-space gate, not proof against all runtime allocations.

For explicit entries in a PS2 ELF or raw ROM instead:

```bash
python3 tools/ee_aot_generate.py --elf /absolute/path/game.elf \
  --pc 0x00200000 --output source/core/recompiler/ee_aot_generated.inc
python3 tools/ee_aot_generate.py --image /absolute/path/bios.bin \
  --base 0xbfc00000 --pc 0xbfc00000 \
  --output source/core/recompiler/ee_aot_generated.inc
```

Addresses above are syntax examples; supply verified entries from your image.
ELF input requires little-endian ELF32 MIPS and executable PT_LOAD backing.
The source archive ships an empty generated table. Private profiles and
generated guest-derived C stay local and must not be committed or added to
public source archives. Restore the empty table before publishing source.

## Test build and installation

The separately supplied DOL/ELF contains 1,024 generated blocks / 5,982
instruction bodies selected from the user's existing BIOS dump. It still
loads the BIOS from the usual SD path; this is not a replacement BIOS.
The existing R1378-B GX/CHD features and build options are retained.
Use the same ARM worker and settings as R1378; this branch changes EE code.

For Wii, install the DOL as `apps/gekko2/boot.dol`, preserving the existing
app assets, and cold boot. For Dolphin, load the ELF. Keep the working build
for comparison. AOT is compiled only with `GEKKO2_EE_AOT`; execution also
requires the existing EE JIT and EE blocks options. Log line
`EE_AOT blocks=1024 retired=...` confirms actual AOT retirement. The counter
is cumulative for the process and separate from the existing JIT counters.

## Validation

See `validation/aot-host-tests.log`, `validation/aot-input-tests.log` and
`validation/aot-ppc-tests.log` for the completed checks. Host tests compare
registers, upper lanes, HI/LO, PC, delay slots, COP0 and memory against the
actual EE interpreter. Explicit guards cover source changes, partial exits,
Count/Compare interrupts, budgets, scheduler quantum limits, changed TLB
mapping and MMIO rejection. Linked-PPC tests execute the target ELF with
modeled platform services and compare EE/timer/IRQ/display states.
They do not replace a physical Wii boot and speed test.
