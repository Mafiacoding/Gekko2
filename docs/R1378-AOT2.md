# R1378-AOT2 — hybrid EE, IOP, VU0 and VU1 static compilation

AOT2 extends the tested AOT1 workflow to all four CPU execution paths. It
specializes instruction words into C before the Wii build, so the target
compiler emits native PowerPC code for selected observed instructions.
No executable code is imported from an external launcher. Quiver is a
launcher, and its N64 recompilers were not transplanted into this emulator.

| Path | Implementation | Preserved boundary |
| --- | --- | --- |
| EE scalar | Wrapping and signed arithmetic, multiply/divide, shifts, traps, SA, branches | Live source/TLB checks and per-instruction retirement |
| EE complex | Exact-word COP0/COP1/COP2/MMI handlers compiled from shared scalar bodies | Original control, vector, exception and mapping side effects |
| EE memory | Scalar, merge, FPU, quadword and VU transfers | Proven safe RAM only; unsafe/MMIO accesses fall back |
| IOP | Exact-PC scalar, memory, conditional branch and COP0 handlers | Original tick/HLE admission, load delay, BD/TAR, operand faults and IRQ retirement |
| VU0/VU1 | Exact-word upper/lower handlers compiled from shared bodies | Existing Q/P, flags, conflicts, branch/E-bit and VIF/GIF pipeline |

The EE scalar switch and specialized complex functions include the same
source fragments. VU half functions likewise share bodies with the scalar
interpreter; constant instruction fields let the C compiler remove decoding.
IOP bodies share the existing decoded switch and use its precise prepare and
retire callbacks. No separate hand-maintained copy of the operation bodies
is introduced. A missing complex companion handler declines before changing
EE state. Every static handler is immutable for the build lifetime.

## Test build

The supplied build uses the user's existing BIOS run, sampled on the host:

- 512 EE entries with 3,536 instruction bodies.
- 256 IOP entries, executed one original scheduler tick at a time.
- 44 VU upper words and 64 lower words from uploaded VU0/VU1 micro images.
- devkitPPC GCC 16.1.0, floating-point contraction disabled consistently.
- MEM1 static end `0x815fd440`; 2,108,352 bytes remain before the MEM1 end.

The block count is bounded to preserve Wii memory. This size check rejects
out-of-range segments and requires at least 1 MiB to remain; it does not
prove that all future runtime allocations will succeed. The normal R1378-B
GX, CHD, controller and ARM-worker build options are retained. Use the existing
ARM worker from that build; this change does not replace it.

## Validation

`validation/aot2-native.log` records:

- 4,500 EE interpreter comparisons, including 128-bit lanes and coprocessor state.
- 1,928 VU0/VU1 pipeline comparisons with Q/P, I/E, branch delay and side effects.
- 255 IOP comparisons with pending loads, BD state and exact EE callbacks.
- 37 existing MMI, FPU, coprocessor, exception, VU and system regressions.

`validation/aot2-ppc.log` executes the actual linked PowerPC binary with modeled
platform services: 30 EE, 32 IOP and 48 VU comparisons all pass and exercise
the static handlers. `validation/aot2-input.log` checks three input/size suites.
These are executable correctness checks, not physical Wii/Dolphin boot tests
or FPS measurements.

## Reproduce privately

Run from the source root with a locally supplied BIOS:

```bash
python3 tools/verify_ee_aot.py
python3 tests/test_ee_aot_inputs.py
../ee_aot_profile_host /absolute/path/bios.bin /absolute/path/profile.json 50000000
export DEVKITPRO=/absolute/path/devkitpro
bash tools/build_ee_aot.sh /absolute/path/profile.json
```

The profiler produces the JSON and `.vu0.bin` / `.vu1.bin` companions. These
are private guest-derived files. The build generates all four native tables
from them; the published source package contains empty tables instead.
`EE_AOT_MAX_BLOCKS` can set the EE profile limit; the default is 512, and
`verify_wii_memory.py` is always the final build gate.

For explicit ELF/raw or synthetic inputs, use `ee_aot_generate.py` with both
`--output` and `--complex-output`. VU and IOP have separate generators.
Never commit the profile, micro images or generated guest-derived tables.

## Installation and runtime evidence

For Wii, replace `apps/gekko2/boot.dol` with the supplied DOL, keeping existing
app assets and worker files. Cold boot with the same BIOS and options as the
working R1378 build. Dolphin can load the ELF. Enable EE JIT + EE blocks,
IOP JIT and VU JIT to exercise all static paths; each existing CPU toggle
still disables the corresponding path. Log lines `EE_AOT` and `IOP_VU_AOT`
report actual static execution, separately from runtime JIT statistics.
Counters are cumulative for the process.

## Explicit remaining limits

This completes the implemented **hybrid generation/build/execution workflow**
for EE, IOP and both VUs. It does not complete PS2 hardware emulation or every
item in the separate dynarec roadmap. EE kernel/SYSCALL/BREAK paths, unsafe
memory, IOP HLE calls/unselected instructions and changed code keep their
existing execution routes. Unknown or previously missing architectural
operations remain missing; preserving the current interpreter is not proof
of hardware accuracy. VU M synchronization, full cycle/pipeline accuracy,
general 128-bit inter-block residency, patched tail linking and physical Wii
acceptance remain outside this checkpoint. No faster boot or FPS claim is made.
